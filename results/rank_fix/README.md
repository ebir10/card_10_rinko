# ランク判別バグ修正 記録(行分離ロジックの改修)

古典的CV(`classify.py`)のランク判別で、通常条件(E)なのに`C08`が`Q`に、
`CK`が`Q`に誤判定される既知の問題があった。原因を特定し修正した。
この修正の**前**と**後**の結果を、比較できるようこのフォルダに分けて保存している。

- `before/` … 修正前(コミット `d985c7c`)の評価結果一式
- `after/`  … 修正後(コミット `9d68690`)の評価結果一式。`results/comparison.json`等、
  リポジトリ直下の現行結果と同じ内容。
- `before_after_accuracy_chart.png` … 両者を並べたグラフ(古典的CVのみ、全5条件)

## 原因

コーナー領域(左上、ランク文字が上段・スートマークが下段)から文字輪郭を
検出し、y座標でグルーピングして「行」に分ける処理(`classify._glyph_rows`)
に2つの問題があった。T・E計104枚を実測して特定:

1. **Q(絵札)4種類全て**: ランク文字「Q」の下に伸びる裾とスートマークの
   実際の間隔が **4〜6px** しかなく、当時の許容ギャップ`ROW_GAP_TOL=6px`
   だと「同じ行」と誤判定され、ランク文字とスートマークが1つの塊に
   融合していた。融合した塊をそのままランクのテンプレートとして
   照合すると、他のランクよりもQのテンプレート(元々縦長でスートマーク
   込みの分だけ他よりノイズが多い)に類似度で負けてしまい、
   `C08→Q`・`CK→Q`のような誤判定を引き起こしていた。
2. **C08 / C04 / CK などクラブ系の一部**: コーナー切り出し領域
   (`CORNER_W_FRAC=0.17`)の右端ぎりぎりに、カード中央の別のクラブピップの
   切れ端が幅8px程度のノイズ輪郭として写り込んでいた。このノイズが
   ランク行とスート行の間に挟まることで、逐次結合方式のクラスタリングが
   連鎖的に全体を1行にまとめてしまっていた。

いずれも「本来2行に分かれるべきコーナーが1行に潰れる」という同じ症状で、
潰れた行をそのまま`extract_rank_glyph()`が使うため、ランク文字にスート
マーク(やノイズ)のピクセルが混入し、テンプレート照合を狂わせていた。

## 修正

`classify.py`:

- `MIN_GLYPH_WIDTH = 15`(新規)を輪郭フィルタに追加し、幅15px未満の
  輪郭(ノイズ)を除外(問題2の対策)
- `ROW_GAP_TOL` を `6` → `2` に縮小(問題1の対策)。T・E全104枚で
  実測した結果、0〜2pxならどのカードも正しく2行(ランク/スート)に
  分離できることを確認済み。文字内の複数輪郭(例: 「10」の「1」と「0」)は
  y範囲が重なる=ギャップが負なので、この値を下げても結合され続ける
  (=同じ文字が分割される心配はない)。

## 結果(古典的CV、全52枚、ランク正解率)

| 条件 | 修正前 | 修正後 |
|---|---:|---:|
| 通常(E) | 96.2% (50/52) | **100%** (52/52) |
| 傾き(合成) | 92.3% (48/52) | **100%** (52/52) |
| 傾き(実写) | 75.0% (39/52) | **80.8%** (42/52) |
| 照明変化(合成) | 75.0% (39/52) | 75.0% (39/52, macroF1は0.757→0.770に改善) |
| 照明変化(実写) | 75.0% (39/52) | **76.9%** (40/52) |

YOLOv8側はこの修正の対象外(全条件で元々100%近辺、影響なし)。

## 結論

「本来除去できるはずだった実装バグ」(行融合)を取り除いたことで、
通常条件・傾き(合成)は100%に到達した。一方、傾き(実写)・照明変化
(合成/実写)は改善しつつも75〜81%止まりであり、これは行融合とは別の
要因(遠近歪みによるコーナー位置ズレ、輝度ムラによるOtsu二値化の破綻)が
引き続き支配的であることを示している。「古典的CVは幾何・輝度変化その
ものに弱い」という結論自体は変わらない。
